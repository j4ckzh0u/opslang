# 可恢复中继传输

可恢复中继传输是控制器侧文件能力，组合内容哈希去重、SFTP 偏移续传和临时 HTTPS 分层扇出。功能由 `file.distribute` 和 `file.collect` 的显式选项启用。

## 部分文件协议

最终路径旁保存 `<dest>.opslang.part` 和 `<dest>.opslang.part.json`。元数据记录会话、源大小、SHA-256、确认偏移和更新时间。恢复前会验证元数据、偏移和末尾确认块；异常状态从零开始并写入 warning。

完整文件必须通过大小和 SHA-256 检查，随后原子 rename 到最终路径。已匹配的最终文件返回 `skipped`。

启用 `compress=true` 时，部分文件保存的是 gzip 字节流，恢复偏移针对压缩对象。传输完成后目标端解压到临时文件，使用原始文件大小和 SHA-256 校验，校验成功后再原子替换最终路径。

## 中继拓扑

计划器优先使用目标显式 `relay_group`，其次使用 `tags.relay_group` 和全局组，最后按 IPv4 `/24` 或 IPv6 `/64` 分组。默认至少 20 个组员才启用中继，每个中继最多服务 100 个下游目标。

候选中带 `relay=true` 标签的目标优先，其余按稳定目标标识排序。候选失败后依序切换，未完成目标使用直接 SFTP。

## HTTPS 会话

- 每个服务只暴露固定 `/file`。
- 随机会话 Bearer token 控制访问。
- 客户端固定 TLS 叶证书 SHA-256 指纹。
- 服务有明确 TTL 和并发上限。
- 客户端拒绝重定向并验证响应哈希。
- 中继只接收短时会话参数，不接收其他目标的 SSH 凭据。

## 分层收集

收集采用方案 2：控制端通过 SSH 要求每个源主机启动受令牌和 TLS 指纹保护的临时 HTTPS 文件服务，中继主机执行 `relay fetch` 将该文件拉取到中继临时路径，控制端再从中继通过 SFTP 续传到 `dest_dir/<host>/<basename>`。每个源主机使用独立会话和独立中继临时文件，确保多主机收集不会混用内容；中继会话失败会回退到控制端直连。

## 结果字段

`transfer_source` 标识 `relay_seed`、`relay:<host>` 或 `direct_sftp`。`resumed_bytes` 表示复用字节，`transferred_bytes` 表示本次实际线传输字节，`warnings` 保留候选失败、恢复重置和清理问题。

## 验证

测试覆盖真实 SSH/SFTP、真实本地 HTTPS、候选切换、直接回退、错误令牌和指纹、恢复偏移异常，以及 1000/10000 主机结果守恒和流量上界。
