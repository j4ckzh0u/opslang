# 执行引擎

执行引擎是把 OpsLang AST 转换为实际运维操作的路径。项目提供解释器、Runner 和 AOT 三种路径，共享 opsspec 操作契约与 ops-core-sdk 实现。

## 三种路径

| 路径 | 代码位置 | 典型用途 |
|------|----------|----------|
| 解释器 | `internal/interpreter` | 本地调试、`opsctl run`、REPL |
| Runner | `internal/runner`, `cmd/ops-runner` | 通过 SSH 执行 JSON 指令包 |
| AOT | `internal/compiler` | 生成独立静态二进制 |

## 选择逻辑

`internal/compiler/mode_selector.go` 实现自动模式选择。用户也可通过 CLI 指定执行模式。目标架构由 SSH 控制面检测，构建使用 `CGO_ENABLED=0`。

## 一致性

`internal/opsspec/spec.go` 是操作名称、参数和作用域的单一事实源。`internal/opsspec/consistency_test.go` 和各引擎的一致性测试用于阻止 registry 或 codegen 漏接操作。

## 安全边界

控制器专用操作只能在控制端执行。权限检查分布于解释器运行时、AOT 编译期和 Runner 运行时。Runner 可在执行前验证指令包签名。
