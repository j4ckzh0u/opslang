# 断点续传与分层中继需求

## 简介

本功能为 `file.distribute` 和 `file.collect` 增加可恢复传输，并为大规模文件分发增加按网络拓扑分组的中继传输。目标是在连接中断后复用已传输字节，同时降低控制端向大量目标分发同一文件时的出口流量。

## 术语

- **控制端**：运行 `opsctl` 和 OpsLang 脚本的主机。
- **目标主机**：接收分发文件或提供收集文件的远程主机。
- **部分文件**：传输期间保存的临时文件，完成校验后原子替换最终文件。
- **中继主机**：拓扑组内先从控制端接收文件，再向同组目标提供文件的主机。
- **拓扑组**：根据 inventory 标签或 IP 前缀划分的一组目标主机。
- **传输会话**：一次文件分发或收集调用产生的有界执行过程。

## 需求

### 需求 1：可恢复上传

**用户故事：** 作为运维人员，我希望文件分发在短暂连接故障后从已确认位置继续，以减少重复传输流量和恢复时间。

#### 验收标准

1. WHEN 用户为 `file.distribute` 启用恢复传输，系统应将数据写入目标路径对应的部分文件。
2. WHEN 部分文件包含与当前源文件一致的已确认前缀，系统应从已确认偏移量继续上传。
3. IF 部分文件大于源文件或已确认前缀不匹配，系统应重新建立部分文件并从偏移量零上传。
4. WHEN 上传字节数达到源文件大小，系统应校验完整 SHA-256，并在校验成功后原子替换最终文件。
5. IF 传输被取消或连接中断，系统应保留有效部分文件供下一次尝试复用。

### 需求 2：可恢复下载

**用户故事：** 作为运维人员，我希望文件收集在短暂连接故障后继续下载，以减少大日志和归档文件的重复流量。

#### 验收标准

1. WHEN 用户为 `file.collect` 启用恢复传输，系统应将数据写入本地目标路径对应的部分文件。
2. WHEN 部分文件包含与远程源文件一致的已确认前缀，系统应从已确认偏移量继续下载。
3. IF 部分文件大于远程源文件或已确认前缀不匹配，系统应重新建立部分文件并从偏移量零下载。
4. WHEN 下载字节数达到远程源文件大小，系统应校验完整 SHA-256，并在校验成功后原子替换最终文件。
5. IF 本地目录为空、远程源文件为空或上下文已取消，系统应返回明确且可测试的结果。

### 需求 3：内容寻址跳过

**用户故事：** 作为运维人员，我希望目标文件内容已经一致时跳过传输，以避免重复占用带宽。

#### 验收标准

1. WHEN 最终目标文件大小和 SHA-256 与源文件一致，系统应返回 `status=skipped` 和 `changed=false`。
2. WHEN 最终目标文件内容不同，系统应执行恢复传输或完整传输。
3. IF 远端元数据或校验和读取失败，系统应记录失败原因并按照配置的重试策略处理。
4. WHEN 内容寻址检查启用，系统应在发送文件主体前完成目标内容判断。

### 需求 4：分层中继分发

**用户故事：** 作为大规模集群运维人员，我希望同一拓扑组只从控制端接收一份文件，以降低控制端出口流量。

#### 验收标准

1. WHEN 用户启用中继且目标数量达到中继阈值，系统应将目标划分为一个或多个拓扑组。
2. WHEN inventory 提供拓扑标签，系统应优先使用拓扑标签划分目标。
3. WHEN inventory 缺少拓扑标签，系统应使用可解析的 IP 前缀划分目标，并将无法解析的目标放入直接传输组。
4. WHEN 拓扑组包含多个可用目标，系统应按稳定规则选择中继主机，并确保相同输入产生相同计划。
5. WHEN 中继分发成功，控制端应向每个拓扑组发送至多一份完整文件主体。
6. IF 中继主机失败，系统应选择组内下一候选主机；候选耗尽后，系统应对未完成目标执行控制端直传。
7. WHEN 所有目标处理完成，系统应为每台目标主机返回独立结果，并标明传输来源和恢复字节数。

### 需求 5：安全与清理

**用户故事：** 作为安全管理员，我希望中继和恢复文件受到完整性校验与生命周期约束，以防止错误内容替换生产文件或临时服务长期驻留。

#### 验收标准

1. WHEN 中继提供文件主体，系统应使用不可预测的会话凭据限制访问范围和有效期。
2. WHEN 目标从中继获取文件，系统应在原子替换前校验文件大小和 SHA-256。
3. WHEN 传输会话结束或超时，中继主机应停止临时传输服务并清理会话凭据。
4. IF 校验失败，系统应保留最终目标文件原内容，并返回结构化错误。
5. WHEN 部分文件超过配置的保留期限，系统应允许后续传输安全替换该部分文件。

### 需求 6：兼容性与可观测性

**用户故事：** 作为 OpsLang 用户，我希望现有脚本继续工作，并能明确观察恢复与中继行为。

#### 验收标准

1. WHEN 脚本省略新增选项，系统应保持当前直接 SFTP 行为和返回字段兼容性。
2. WHEN 恢复或中继启用，系统应在每台主机结果中返回传输来源、已恢复字节数、总线传输字节数和最终校验和。
3. IF 新增选项类型或范围无效，解释器应返回包含选项名称的错误。
4. WHEN 运行 10000 主机模拟测试，系统应生成一条结果对应每台主机，并验证无重复与无遗漏。
5. WHEN 中继模拟测试使用多个拓扑组，控制端主体出口字节数应受拓扑组数量与直传回退数量约束。

## 范围边界

- 本规格包含普通文件的分发与收集。
- 本规格包含 Linux amd64 和 arm64 目标上的中继执行。
- 本规格保留现有 SSH/SFTP 认证和主机密钥策略。
- 压缩传输属于后续独立功能。
- 对象存储和外部 HTTP 服务属于后续独立功能。
